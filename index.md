## Concepts — what a thing is

Background. Read when a method references something you do not recognise.

| Page | What it covers |
|---|---|
| [pw-manual-map](concepts/pw-manual-map.md) | **Start here for anything in the PowerWorld manual.** The manual is organised by ribbon tab, so a research subject lands in three or four chapters its contents page never shows together. 25 subjects, each with its topic count and the chapter files that hold it; nine have a detail page here. |
| [powerworld-help-corpus](concepts/powerworld-help-corpus.md) | What the offline manual capture is and what it does **not** document. 164 of 1,670 topics carry no usable body and sit interleaved with real ones; superseded version-9 API pages sit beside current ones and answer confidently with the wrong API; the figures are referenced but were never committed, so every image link is broken. Also: neither PowerWorld manual holds a per-object field catalog. |
| [pw-power-flow](concepts/pw-power-flow.md) | Solution theory and every control acting during the solve — remote regulation, Mvar sharing, line-drop compensation, droop with deadband, island AGC. Voltage Conditioning moves generator setpoints *and* switched shunts, and its title says neither. |
| [pw-contingency](concepts/pw-contingency.md) | Defining contingencies, the element dialog per element type, the options that change the answer, RAS, and reading results. Reference-state handling decides what violations are measured against and is easy to skip. |
| [pw-timestep-sim](concepts/pw-timestep-sim.md) | The quasi-static Time Step Simulation tool. Only a quarter of the story: the script commands that launch a run, the programmatic entry point and the batch engine are three other chapters. |
| [pw-scripting-automation](concepts/pw-scripting-automation.md) | AUX export formats, script execution, and SimAuto function-by-function. The manual explicitly declines to list field variables — verify names against the live schema. |
| [pw-data-model](concepts/pw-data-model.md) | The object and field reference: case information displays, filters, expressions, key fields, and object dialogs. Edit mode and run mode document the same object twice with different writability. |
| [pw-pv-qv](concepts/pw-pv-qv.md) | PV and QV curves — transfer margin and reactive margin at a bus. Most titles here are bare dialog-tab names, so a title search will not find them. |
| [pw-interfaces](concepts/pw-interfaces.md) | The interface object, flowgates and nomograms — the monitored element behind every transfer study. The manual has no chapter for it; it is scattered across four. |
| [pw-injection-groups](concepts/pw-injection-groups.md) | Injection groups and participation points — what a transfer is scaled and ramped on. Also has no chapter of its own, and the study chapters depend on it silently. |
| [aux-only-powerworld](concepts/aux-only-powerworld.md) | A `.aux` file is a complete program — open a case, edit it, solve it, export CSVs, write the log and exit, with no Python and no SimAuto call at all. Field names must come from esapp's schema or PowerWorld's own field export, never from the *Auxiliary File Format* manual, which has no per-object field catalog. |
| [builtin-distributed-computing](concepts/builtin-distributed-computing.md) | The checklist [parallel-contingency-solve](parallel-contingency-solve.md) never got to use: what Simulator's own Distributed Computing add-on needs before it runs anything on a remote or even a local core, and the settings that make it degrade to serial quietly instead of erroring. |
| [buscat-and-voltage-control](concepts/buscat-and-voltage-control.md) | The `BusCat`/`Type` string PowerWorld assigns every bus during a solve is the best diagnostic for why a case didn't solve the way you expected — read it before scripting anything that toggles remote regulation, Mvar sharing, line-drop compensation, or droop. |
| [case-impedance-completeness](concepts/case-impedance-completeness.md) | A case can solve DC power flow for years while carrying no resistance and no line charging at all. DC reads only `X`, so nothing ever complains. |
| [case-restructuring-tools](concepts/case-restructuring-tools.md) | Six Edit-Mode topology tools, each with a silent-failure mode: equivalencing permanently deletes what it reduces, bus merging can silently drop a multi-section-line's grouping record, line tapping fabricates a fault-analysis impedance out of nothing, and renumbering reads its target from a field you have to populate yourself. |
| [case-to-case-device-transplant](concepts/case-to-case-device-transplant.md) | Copy a set of devices from one case into another without rebuilding the chain that produced them, by carving a filtered AUX out of the source case. |
| [contingency-linked-sensitivities](concepts/contingency-linked-sensitivities.md) | Four tools between plain contingency analysis and single-outage LODF: a batch N-2 pre-screen, a per-violation remediation ranking, a live-case-mutating diagnostic, and a fix for a specific blind spot in linear contingency analysis. |
| [copper-plate](concepts/copper-plate.md) | Strip every branch, load and shunt and leave a single slack bus, so generators dispatch to total system load with no transmission constraints. |
| [data-check-objects](concepts/data-check-objects.md) | A `DataCheck` is a named, reusable pass/fail rule against case data that shows up as its own field on every object of that type and rolls up per area/zone/owner — replaces hand-rolling the same filter every time a script needs to count rule violations. |
| [datamaintainer-and-object-groups](concepts/datamaintainer-and-object-groups.md) | `DataMaintainer` and `ObjectGroup` let code slice a case along lines that aren't Area/Zone/Owner — and each has an inheritance or auto-creation behavior that can silently change what a read or write touches. |
| [difference-case-tool](concepts/difference-case-tool.md) | PowerWorld ships its own case-comparison engine — `Removed<Type>` object types, per-field tolerances, a base-to-present AUX export — that a hand-rolled pandas diff duplicates without knowing it exists, though renumber pairing and retirement classification still need project-specific logic on top. |
| [esapp-environment](concepts/esapp-environment.md) | What `esapp` is, what it needs to run, and how the `PowerWorld` entry point, the bracket interface and the `SAW` wrapper fit together. |
| [esapp-script-command-wrappers](concepts/esapp-script-command-wrappers.md) | Why you call `pw.esa.TimeStepDoRun()` rather than `RunScriptCommand("TimeStepDoRun;")`, and the roughly 41 actions where no wrapper exists. |
| [esapp](concepts/esapp.md) | The full API map for `esapp`: top-level imports, architecture, and what the package can actually do. |
| [filter-expression-language](concepts/filter-expression-language.md) | One grammar underlies Advanced Filters, Model Expressions, String Expressions, and `DataCheck` conditions — read it before writing any `FilterName` string, because a malformed filter doesn't error, it just silently matches nothing. |
| [fixednumbus-and-raw-v34](concepts/fixednumbus-and-raw-v34.md) | RAW v34+ splits each electrical bus into a substation-level node structure, and assuming `BusNum` equals the PSS/E bus number or that IDs stay stable across a `FixedNumBus` assignment gets silently wrong answers — the failures here log a message and move on rather than raising. |
| [generator-dispatch-and-diagnostics](concepts/generator-dispatch-and-diagnostics.md) | The 6 ways Area AGC redispatches to meet ACE, the two merit-order algorithms shared by PV/QV/ATC/scaling tools, and why Voltage Conditioning changes generator setpoints without mentioning generators in its name. |
| [gic](concepts/gic.md) | Geomagnetically induced currents: what they do to transformers during a geomagnetic disturbance, and what PowerWorld models. |
| [gic-modeling-heuristics](concepts/gic-modeling-heuristics.md) | The mechanism behind [gic](gic.md)'s placeholder-data warning: the specific fallback rules Simulator applies when autotransformer status, winding configuration, or grounding resistance are left at `Unknown`/zero, none of which error — each silently changes whether a transformer carries GIC current at all. |
| [glossary](concepts/glossary.md) | Every acronym and piece of jargon this kit uses, defined once. Read the confused-pairs section even if you skip the rest — PWW versus PFW has cost people whole afternoons. |
| [injection-group-participation](concepts/injection-group-participation.md) | A generator's raw participation factor is almost never the number actually used — every consumer renormalizes it over whatever subset of members it considers eligible, so a 70/30 group can distribute 100/0 in one tool and 70/30 in another with no error either way. |
| [interface-elements-and-monitoring](concepts/interface-elements-and-monitoring.md) | An interface's reported flow depends on two independent direction settings and which element types built it — get either wrong and the number is still real, it just measures something else. An unrated auto-inserted interface silently defaults its limit to 0. |
| [island-and-breaker-grouping](concepts/island-and-breaker-grouping.md) | Four free tools compute island and breaker-boundary structure without the paid Integrated Topology Processing add-on. Two silent traps: an Area spanning more than one island gets AGC turned off with no error, and a case-to-case topology diff can flag pure bus-renumbering as a real change. |
| [limit-monitoring-and-scaling](concepts/limit-monitoring-and-scaling.md) | Why an obviously-overloaded branch never shows up in `overloads()`, contingency analysis, ATC, or OPF: reporting is gated by a chain of flags upstream of the rating, and one wrong link makes the device invisible everywhere at once. Scaling has the same shape — one AGC-filtering option silently strands the remainder on the slack bus. |
| [lodf](concepts/lodf.md) | Every branch's post-outage flow for every single-branch outage, from one matrix factorization. Measured live it is not an approximation of DC contingency analysis; it is the same answer. |
| [loss-voltage-driving-point-sensitivities](concepts/loss-voltage-driving-point-sensitivities.md) | Loss sensitivities are meaningless outside a differenced pair, flow/voltage sensitivities read zero at every PV bus unless AVR is disabled, and driving-point impedance depends entirely on which of three Ybus models built it — three sensitivity families that share nothing with PTDF/LODF but the word. |
| [network-cut-and-query-tools](concepts/network-cut-and-query-tools.md) | Four topology-query tools that look similar but aren't: Network Cut is a manual boundary, Facility Analysis is an actual min-cut over pure connectivity, and Radial Bus Paths/Shortest Path share a distance measure that silently clamps negative field values. None verify a boundary is complete before running — an ill-defined one just fails to bisect rather than erroring. |
| [objectid-identification-traps](concepts/objectid-identification-traps.md) | Two branch shapes need extra identifiers a normal 3-field `ObjectID` doesn't carry, and getting the count wrong doesn't error — the parser accepts both shapes contextually, so a missing or extra identifier silently resolves to the wrong section or winding. |
| [opf-preconditions](concepts/opf-preconditions.md) | LP OPF needs three independent preconditions at once — an area under `BGAGC = "OPF"`, AGC-able generators, and a real cost model — and misses a fatal error rather than a degraded solve. Synthetic cases routinely ship with all three off. |
| [parallel-contingency-solve](concepts/parallel-contingency-solve.md) | PowerWorld's own distributed `CTGSolveAll` never spawns workers here and silently degrades to serial. Split the contingency set across N processes instead. |
| [per-unit-basis-discipline](concepts/per-unit-basis-discipline.md) | A per-unit value is meaningless without the base it was normalized against, and it looks like a plain scalar, so it gets copied between sources and summed. |
| [post-contingency-aux-state-carryover](concepts/post-contingency-aux-state-carryover.md) | Contingency Analysis's per-contingency aux/script hooks restore reference state differently depending on solve method — under a linear method or DC power flow, the second hook's state is never restored between contingencies, so any change it makes silently contaminates every later contingency in the batch. |
| [powerworld-inertia-and-cost-data](concepts/powerworld-inertia-and-cost-data.md) | Four case-data facts to know before touching generator inertia or cost, starting with `Gen.TSH` being H on a 100 MVA system base rather than the unit's own. |
| [powerworld-script-transfer](concepts/powerworld-script-transfer.md) | Simulator 25 beta watches a directory and executes any `.aux` dropped in it, writing the log back to a text file — a channel into PowerWorld that needs no COM, no SimAuto and no SimAuto licence. Undocumented in the manual. |
| [powerworld-simauto](concepts/powerworld-simauto.md) | The Windows COM server every PowerWorld Python script ultimately talks to, its SAW mixin architecture, and the verified raw COM calls. |
| [ptdf-shift-factor-otdf](concepts/ptdf-shift-factor-otdf.md) | What the *transaction* behind a PTDF number represents, and where it bites: loss allocation between seller and buyer is asymmetric not symmetric, transactor type silently changes which generators can move, and an interface holding a contingent element can report a PTDF that ignores the outage you're studying. |
| [pww-data](concepts/pww-data.md) | The PWW binary weather format: gridded variables packed as uint8 per timestep and grid point, with 255 as the NaN sentinel. |
| [raw-epc-roundtrip-traps](concepts/raw-epc-roundtrip-traps.md) | Reading or writing PTI RAW or GE EPC through PowerWorld is not lossless — Simulator reinterprets, discards, or silently converts fields on both read and write, with no error or warning. A save/reload round trip is not guaranteed to match what you started with. |
| [required-fields-for-object-creation](concepts/required-fields-for-object-creation.md) | Required fields are the smaller set PowerWorld demands before it creates a *new* object from a paste, aux `INSERT`, or CSV import — separate from key fields, and a guard against a row full of key fields accidentally fabricating an object. Missing one doesn't error, it skips the creation silently. |
| [scheduled-actions-scripting](concepts/scheduled-actions-scripting.md) | A Scheduled Action Group can sit in the case, inside its time window, looking ready to fire — and never apply, because a separate `Status` flag on the group is Inactive. Code that assumes "in window" means "will run" gets silently wrong topology. |
| [shunt-transformer-dfacts-control](concepts/shunt-transformer-dfacts-control.md) | How switched shunts, SVCs, transformer AVR/Mvar/phase control, and D-FACTS devices coordinate during a solve — and the several ways each silently disables itself with only a log message. |
| [simauto-output-shapes-and-discovery](concepts/simauto-output-shapes-and-discovery.md) | The envelope every raw `pw.esa.*` SimAuto call returns below esapp's DataFrame conversion, plus two field-discovery calls `GetFieldList` can't answer: how many indexed slots a repeatable field family has, and how to look up a field by name instead of pulling the whole list. |
| [solver-mechanics-and-failure-modes](concepts/solver-mechanics-and-failure-modes.md) | The nested loop structure behind every AC solve, the options that change convergence without erroring, and the deterministic algorithm behind island slack selection — read it when a case won't converge or converges to an answer you didn't expect. |
| [timestep-opf-and-storage](concepts/timestep-opf-and-storage.md) | Time Step Simulation can solve each timepoint as an Unconstrained OPF, OPF, or SCOPF, with result storage opt-in rather than automatic — a run that "succeeds" can still produce an empty result grid, and the `.tsb` file can be set to auto-load and auto-run the moment a `.pwb` opens. |
| [timestep-schedules-and-delays](concepts/timestep-schedules-and-delays.md) | Beyond the `.pww` input the weather-to-MW pipeline uses, Time Step Simulation has two other input channels — per-timepoint data columns and reusable Schedules — and a case with schedules, controller time delays, or Time Step Actions already configured won't behave like a plain repeated power-flow solve, with nothing in the output saying so. |
| [timestep-simulation](concepts/timestep-simulation.md) | What a timestep simulation is here: hourly renewable output computed quasi-statically from weather data. It is not a transient-stability study. |
| [timestep-workflow](concepts/timestep-workflow.md) | The whole chain from a `.pww` file to per-generator hourly CSVs, in the order PowerWorld requires it. |
